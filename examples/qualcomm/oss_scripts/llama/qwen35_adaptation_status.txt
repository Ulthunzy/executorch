Qwen3.5-0.8B VLM Adaptation Plan
=================================

Summary
-------
- 适配 qwen3_5-0_8b，但不新增 Runner<float> /
  QNNMultimodalRunner<float>，当前先保持现有 uint16 runtime 路径。
- 不新增 get_logits_output_bit_width、get_attention_mask_io_bit_width、
  logits scale/zero_point、Qwen3.5 cache shape 等 metadata；按当前框架已有逻辑处理。
- 创建并维护 examples/qualcomm/oss_scripts/llama/qwen35_adaptation_status.txt，
  实现过程中持续记录功能、问题和测试结果。

Key Changes
-----------
- 添加 Qwen3.5 model/export 集成：
  - 注册 qwen3_5-0_8b，目标本地模型路径
    /hunter/model/Qwen/Qwen3.5-0.8B。
  - 接入 Qwen3.5 text decoder：DeltaNet linear-attention、Qwen35 RMSNorm、
    M-RoPE、Qwen35ModelWithoutEmbedding。
  - 接入 Qwen35 vision encoder/config/quant recipe；encoder 可先按
    fp16/skip-quant 路径验证。

- 添加 Qwen3.5 quant recipes：
  - 增加 Qwen3_5_0_8BQuantRecipeSpeed。
  - speed recipe 中明确将 output.conv 设置为 QuantDtype.use_16a8w。
  - 不改变当前 logits bitwidth 策略。

- Runtime cache 行为：
  - 为 Qwen3.5 linear-attention state cache 增加明确语义，区别于普通
    append 和 true-SWA circular。
  - 建议新增 cache update enum：
    - kAppend: full-attention KV append/update。
    - kCircular: true-SWA circular update。
    - kFullOverwrite: linear-attention state output 全量覆盖旧 state。
  - Qwen3.5 linear 层使用 kFullOverwrite。

Qwen3.5-0.8B VLM Adaptation Status
===================================

Goal
----
- Adapt qwen3_5-0_8b for the Qualcomm llama export/runtime flow.
- Keep the existing uint16 runtime path; do not add Runner<float> or
  QNNMultimodalRunner<float> in this pass.
- Do not add new logits bitwidth, attention mask bitwidth, logits qparam, or
  Qwen3.5 cache-shape metadata beyond what the current framework already uses.
- Add explicit runtime cache semantics for Qwen3.5 linear-attention state cache:
  full overwrite, separate from append and circular/SWA behavior.

Completed
---------
- Created this adaptation tracking file.
- Wrote the requested Chinese plan at the front of this file.
- Added Python-side Qwen3.5 model/export integration:
  - Registered qwen3_5-0_8b with local repo path
    /hunter/model/Qwen/Qwen3.5-0.8B.
  - Added Qwen35 RMSNorm and gated RMSNorm.
  - Added Qwen35 DeltaNet linear-attention, Qwen35 decoder layer,
    M-RoPE handling, and Qwen35ModelWithoutEmbedding.
  - Added Qwen35 vision encoder/config and Qwen35 encoder quant recipe.
  - Added Qwen3.5 tokenizer multimodal special-token mapping.
  - Added Qwen3.5 vision dataset patch preprocessing.
- Added Qwen3.5 decoder M-RoPE position generation for Python SQNR/inference.
- Added Python cache update handling for linear-attention state full overwrite.
- Added local transformers/lm_eval compatibility handling in decoder_utils and
  decoder_runtime_evaluator so `AutoModelForVision2Seq` missing from the
  installed transformers package no longer blocks direct SQNR/helper imports.
- Added Qwen3_5_0_8BQuantRecipeSpeed.
  - output.conv is explicitly annotated as QuantDtype.use_16a8w.
  - No logits bitwidth/qparam override was added.
- Updated llama export compile options:
  - Qwen3.5 vision encoder uses fp16/skip-quant for the first validation path.
  - Qwen3.5 text decoder disables mha2sha.
  - Weight sharing remains disabled for kv-only export.
- Updated export wrapper behavior for Qwen3.5:
  - Filters extra HF checkpoint keys before strict decoder load.
  - Tags Qwen3.5 linear-attention state cache I/O by full tensor shape.
  - Makes speed recipe skip-calibration effective.
  - Skips hybrid decode/prefill encoding override for Qwen3.5 because the
    graphs are not isomorphic.
  - Supports Qwen3.5 vision encoder layer counting via vision_config.depth.
- Added C++ runtime cache semantics:
  - Added KVManager cache update modes kAppend, kCircular, and kFullOverwrite.
  - Added per-layer cache specs derived from method metadata for qwen3_5.
  - Qwen3.5 equal-sized state caches use kFullOverwrite.
  - Full-overwrite state caches are copied from output buffer to input buffer
    instead of using append or true-SWA circular update.
- Added qwen3_5 C++ multimodal runner handling:
  - VisionLanguageModel::kQwen3_5 parsing and EOS handling.
  - M-RoPE position-id dimension inference from exported method metadata.
  - Prompt position-id generation for text and square-grid image embeddings.
  - Decode position delta support after image tokens.
  - Qwen3.5 image embeddings are inserted directly instead of placeholder
    replacement.
  - Vision chat template emits Qwen3.5 user/assistant format with
    <|vision_start|>/<|vision_end|> and thinking prefill.
- Corrected first-block export strategy:
  - Keep examples/models/qwen3_5/config/0_8b_config.json as the full 24-layer
    source config.
  - Generate a temporary params JSON for each block test.
  - For the first block temp config: n_layers = 4 and layer_types =
    linear_attention, linear_attention, linear_attention, full_attention.
  - The tested path is tok_embedding graph + selected decoder block(s) +
    decoder norm + lm_head/output, and SQNR is measured on lm_head logits.
- Added Qwen3.5 KV/cache qparam alignment after convert_pt2e:
  - Collects each cache input quantize_per_tensor scale/zero_point.
  - Rewrites matching cache output quantize/dequantize qparams to the input
    qparams before saving decode_qdq.pt2 and before QNN lowering.
  - Scoped to qwen3_5 decoder export; logits qparams and bitwidth metadata are
    unchanged.
- Added Qwen3.5 KV/cache input zero-point initialization in the C++ runtime:
  - Exports get_kv_input_{idx}_scale and get_kv_input_{idx}_zero_point metadata
    for Qwen3.5 cache input placeholders.
  - Reads get_kv_input_{idx}_zero_point in QNNMultimodalRunner.
  - Initializes and resets Qwen3.5 uint16 cache input buffers to each cache
    tensor's quantized zero point instead of raw zero.
  - This keeps the existing uint16 runtime path; no float runner instantiation
    was added.
- Removed the stale fixed Qwen3.5 logits qparam override from the quant recipe.
  Qwen3.5 logits scale/zero_point should come from the converted quantized
  graph, not from a hard-coded (1/256, 32768) recipe hook.
- Tightened Qwen3.5 runtime metadata handling:
  - get_kv_input_{idx}_zero_point is now required for Qwen3.5 PTEs.
  - Missing cache qparam metadata is treated as an export/runtime error instead
    of silently falling back to zero.
  - The exported qparams are still static PTQ qparams: they are computed during
    calibration/export and then fixed in that PTE. They are not recomputed per
    runtime prompt or image.

Current Problems
----------------
- Direct Python import smoke test is currently blocked by missing Python
  dependencies in this environment (flatbuffers first; after adding the local
  flatbuffers path, torchao is also missing).
- First-block kv export hit and fixed one encoder preprocessing issue:
  Qwen35 vision preprocess squeezed [1, 784, 1536] to [784, 1536], but the
  exported encoder graph expects the 3D shape. preprocess now preserves the
  dataset tensor shape.
- First-block kv export now completes and writes the expected PTE set, but QNN
  compile logs still contain repeated
  "scale too large for requant qu16->qu16: 19999.916016" diagnostics. The
  process exits successfully, so this is tracked as an accuracy/runtime risk
  for the next SQNR run rather than an export blocker.
- Block1 and block2 kv runtime execution are structurally working on device
  after rebuilding the Android runner, but the full FP32/CPU-QDQ/QNN SQNR
  passes are not accuracy-green yet:
  - Block1 CPU QDQ vs QNN lm_head logits SQNR: 18.293 dB.
  - Block1 FP32 vs CPU QDQ lm_head logits SQNR: 1.877 dB.
  - Block1 FP32 vs QNN lm_head logits SQNR: 1.887 dB.
  - Block2 CPU QDQ vs QNN lm_head logits SQNR: 18.054 dB.
  - Block2 FP32 vs CPU QDQ lm_head logits SQNR: 0.789 dB.
  - Block2 FP32 vs QNN lm_head logits SQNR: 0.808 dB.
  This means the exported QDQ graph and QNN runtime are aligned, but the
  current speed recipe is very lossy versus FP32 for these truncated block
  tests. Treat this as a quantization/recipe risk before calling kv mode fully
  stable.
- Do not treat logits qparams or logits/attention-mask bitwidth metadata as the
  current suspect:
  - The framework already uses uint16 for logits and attention mask in this
    flow.
  - get_logits_output_bit_width and get_attention_mask_io_bit_width are not
    needed for the current Qwen3.5 path.
  - Logits scale/zero_point are computed by PTQ calibration/export and are
    readable from the PTE metadata. Example current values observed from block
    tests:
    block1 scale = 0.000370977243, zero_point = 37081;
    block2 scale = 0.000407945539, zero_point = 37705.
  - CPU QDQ vs QNN SQNR around 18 dB indicates the QNN runtime and exported QDQ
    graph are aligned enough that logits qparam loading is not the first issue.
- Full 24-layer kv generation is now semantically normal after the runtime
  cache zero-point initialization fix and a fresh QNN 2.45 export:
  - Prompt: "描述一下这张图片"
  - max_seq_len = 256
  - Current output starts with a normal Chinese image description:
    "这张图片展示了一个充满生活气息的场景：..."
  - The stale "axon" and mixed-gibberish outputs came from older PTE/runtime
    combinations that did not initialize quantized cache inputs with their
    zero points.
- Direct imports of decoder_utils now work after adding the transformers
  LazyModule compatibility helper locally.

-----------

  - KVManager now counts each cache allocation with the same 4KB alignment used
    by RpcMem::allocate().

    separately.

    aligned allocation accounting.

  - multimodal prompt processor, multimodal token generator, and token
