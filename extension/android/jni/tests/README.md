# QNN LLM JNI smoke test

`QnnChatTemplateTest.java` takes `early.pte` and its tokenizer. It checks exact
echoed input text: no default system message (omitted/null/empty), explicit
system messages on the first turn only, the evaluation driver's inter-turn
newline, reset/reload, zero output budget and cancellation before prefill.
Both legacy constructors and the KV/hybrid config constructor are covered;
plain `generate()` must not add another template. It can be compiled against
the old App AAR to exercise existing descriptors with the new runtime.

`LegacyThinkingDefaultsTest.java` is compiled against the old App AAR and runs
with the new AAR, `early.pte`, and its tokenizer. It checks both legacy constructors
and protected chat after reload. `QnnThinkingTest` also checks the new default
penalty/window (1.05/128) and default protections.

`QnnThinkingTest.java` uses `early.pte` and `loop.pte` generated by
`examples/qualcomm/oss_scripts/llama/model_validation/benchmarks/test_thinking_device.py`.
It takes those two paths and the matching tokenizer.json. Compile it against
the new runtime JAR, then use the app_process flow below. It checks all four
thinking-control combinations in KV/hybrid, per-call toggling without rebuilding
the module, first-prefill EOS, zero output budget, cancellation at the forced
closing token and subsequent KV continuation. These deterministic portable
fixtures exercise the real QNN runner's control flow, not language-model quality.

The companion pytest device tests are opt-in via `ET_THINKING_DEVICE`,
`ET_THINKING_DRIVER`, `ET_THINKING_TOKENIZER_DIR`, and `ET_THINKING_LIBDIR`.
They create isolated temporary device directories and leave existing models,
runtime libraries and benchmark results untouched. Host state-machine/CLI tests:

```bash
python -m pytest backends/qualcomm/tests/test_llama_thinking.py \
  backends/qualcomm/tests/test_llama_driver_options.py
```

`LegacyAarSmokeTest.java` must be compiled against the **old** app AAR's
`classes.jar` and Android SDK `android.jar`. Package its unchanged class files
with the **new** runtime JAR using d8. It checks both legacy constructors,
status return values, chat formatting, echo without disabling thinking,
unload/reload, KV/hybrid auto-detection, prefill cancellation, TextEncoder
array/text encoding, and Module.loadMethod. Pass four device paths: the real
Lincal KV PTE, its tokenizer, `text_encoder.pte`, and `hybrid_ar4.pte`. The
fixture exporter below creates both small PTEs. It also works with the app's
fbjni 0.5.1 Java/native dependency.

`QnnLazyLoadCancelTest.java` is also compiled against the old AAR. Run it with
the real KV PTE and its tokenizer. It issues `stop()` 300 ms into the first chat
call (use a PTE whose cold QNN load is slower than this), checks zero committed
prompt/output tokens, resumes without resetting, and repeats after `unload()`.

`test_encrypted_model_loader.py` tests the native loader under ASan/UBSan on the
host (requires `build-x86/libexecutorch_core.a`, OpenSSL headers, and Python
`cryptography`). It covers plain/legacy/ETENC1 inputs, AES-128/256, chunk boundaries,
wrong/missing keys, tampering, and truncated inputs. Run with `pytest`.

To test BoringSSL and JNI on Android, wrap the small hybrid fixture with test keys:

```bash
python extension/android/jni/tests/export_encrypted_model_fixtures.py \
  /tmp/qnn-runner-fixtures/hybrid_ar4.pte /tmp/qnn-encrypted-fixtures
```

Push the output directory and compile/package `QnnEncryptedModelTest.java` against
the new runtime JAR. It takes three device paths: plain `hybrid_ar4.pte`, tokenizer,
and encrypted fixture directory. It compares generated output, tests unload/reload
with both formats, and requires useful error codes for bad containers. These
fixtures contain public test keys and must not be used to protect real models.
It also checks that null/empty `dataPath` permits plain, legacy, and ETENC1 loading
and reloading, while nonempty paths retain the external-data restriction.

`check_aar_api.py OLD.aar NEW.aar` compares every public class and JVM member
descriptor, including return types. It permits additive APIs and ignores
package-private compiler-generated classes; it does not prove model quality
or full behavioral compatibility for every backend.

`QnnLlmSmokeTest.java` exercises the real Java → fbjni → QNN path on an Android
device with a Lincal KV PTE. It checks output-token limits (including zero and
one), EOS, greedy reproducibility after reset, reset after crossing SWA 512,
cross-thread stop during prefill and decode, per-call temperature, warmup,
shared buffers, and the existing generate overload.
It also compares incremental turns after a one-token limit with replaying the
same token sequence and checks exact continuation budgets after EOS and cancellation
with existing history. Partial prefill must preserve the committed prefix and allow
immediate continuation without reset. Its continuation is compared with a baseline
that receives exactly the committed prefix, both before and after filling SWA 512.
The partial-prefill test schedules a stop after 150 ms on an AR-1 prompt of 400
tokens; run it on the real KV PTE, not the tiny synthetic fixtures below.

`backends/qualcomm/tests/test_llama_prefill_cancel.py` also runs a native test
with deterministic cancellation immediately after AR-4/AR-128 execution and
before cache commit. It checks the first and third blocks, exact K/V contents
before and after SWA wraparound, continuation without reset, and exclusion of
uncommitted tokens from repetition history under ASan/UBSan.

Build the Android JNI library with QNN enabled and the Kotlin runtime JAR using
`./gradlew :executorch_android:bundleLibRuntimeToJarDebug`. Compile this test
with `javac` against that JAR and the Android SDK `android.jar`. Use the SDK's
`d8` to package the test classes, runtime JAR, matching fbjni `classes.jar`,
`nativeloader` JAR, and Kotlin stdlib into `smoke.jar`.

Put `smoke.jar`, the new JNI library renamed `libexecutorch.so`, its matching
`libfbjni.so`, `libc++_shared.so`, `libqnn_executorch_backend.so`, and the QNN
HTP/System/stub/skel libraries in `/data/local/tmp/llama-jni-smoke`.
The QNN libraries must be inside the Java native-library search path as well
as the shell library path. Then run:

```bash
adb shell 'cd /data/local/tmp/llama-jni-smoke && \
  export LD_LIBRARY_PATH=/data/local/tmp/llama-jni-smoke && \
  export ADSP_LIBRARY_PATH=/data/local/tmp/llama-jni-smoke && \
  CLASSPATH=smoke.jar app_process \
    -Djava.library.path=/data/local/tmp/llama-jni-smoke \
    /data/local/tmp/llama-jni-smoke QnnLlmSmokeTest \
    /path/on/device/kv_llama_qnn.pte /path/on/device/tokenizer.json'
```

The test prints `PASS` and exits after closing the modules. Native per-call
statistics are also available in `adb logcat` under the `ExecuTorch` tag.

## Hybrid and tokenizer boundaries

Generate tiny portable test PTEs in the activated ExecuTorch environment:

```bash
python extension/android/jni/tests/export_qnn_runner_fixtures.py /tmp/qnn-runner-fixtures
```

Compile and package `QnnLlmBoundaryTest.java` with the same Java dependencies.
This test uses the QNN runner with portable methods (no model calibration or
QNN compilation). It exercises full-context AR-16 prefill, chunked AR-4 capacity,
explicit reset, and exact BOS/EOS insertion counts. Put both PTEs on the device,
along with the real Qwen/Lincal tokenizer and the Llama3 tokenizer fixture from
`extension/llm/tokenizers/test/resources/hf_tokenizer_dir/tokenizer.json` (rename
the fixture to avoid overwriting the model tokenizer). With the same environment
and Java library path as above, invoke:

```bash
CLASSPATH=smoke.jar app_process -Djava.library.path=/data/local/tmp/llama-jni-smoke \
  /data/local/tmp/llama-jni-smoke QnnLlmBoundaryTest \
  /path/on/device/hybrid_ar16.pte /path/on/device/hybrid_ar4.pte \
  /path/on/device/tokenizer.json /path/on/device/llama3-test-tokenizer.json
```
